## 0. 事前確認

Llm.build_promptが全工程に辞書全件JSONを付加し、ReviewClients.reviewも同じ全件をGemini・Sarashinaへ送っている。辞書検索は既に幅だけの正規化と優先順位を持つが、語句の包含と位置対応を事前適用する共通層が必要。比較入力のWhisperは辞書で書き換えてはならない。

## 1. 実装順序

- [x] P1/R1 R2: 原文の位置付き辞書適用と未確定部分の入力契約を追加。一次基準は未確定区間だけを照会し、登録済み区間とローカル結合する。長い語句・優先順位・利用者の指定読み・全半角・繰返しをテスト後コミットする。
- [ ] P2/R2 R3: 一次全件添付の廃止、二次対象と文脈の絞込み、辞書確定と独立票の分離、再開契約の更新、送信量ログを統合。Whisper実測は無加工で比較し、採用済み登録計画はローカル構築する。関連回帰後コミットする。
- [ ] P3/R4: CLIから回帰・実API照会を実行し、正解付き文脈例、旧方式のローカル生成入力、実送信量と照会数を比較。実APIの失敗・判断不能と精度の限界を記録し、資料を更新してコミットする。

## 2. 境界

全辞書スナップショットは読戻し・競合・履歴のためローカルに保持する。送信には含めない。二次照会には対象語の原文と隣接文の文脈、およびその範囲の事前適用結果だけを渡し、他モデルの答えは渡さない。登録済み語が実TTSと異なる場合も不一致を残し、辞書を根拠に実測を改ざんしない。既存ジョブは入力契約不一致として安全に新規実行を要求する。
