# 読み照会の入力と検証

## 送信前の処理

辞書全件は読戻し・重複競合確認・履歴のためローカルに保存します。全件テーブルをLLMへは送信しません。原文を改変せず、適用した表記・読み・位置を別に記録します。長い語句を優先し、同じ表記は辞書優先順位の小さい行を使います。丸数字などの意味は保ち、ASCIIの全半角だけを一致判定で統一します。置換後のカタカナは再置換しません。利用者や今回の採用判断で明示した読みを優先します。

一次基準の生成では未確定区間だけを照会します。文脈には意味を保つ原文と登録済み読みを適用した文章を渡します。応答の区間ID・対象語・カタカナを検証し、登録済み区間とローカルで結合して全文の読みを作ります。全区間が確定済みなら基準生成のLLM呼出しはありません。

二次モデルには未確定の対象語だけを問い、その語の全出現箇所を含む文と隣接文を添えます。同じ語が異なる文脈で異なる読みになる場合は判断不能として扱います。一次案・他モデルの回答は入力に含めません。登録済み語しかない場合は二次照会を省略します。

## 評価と安全な停止

登録済み読みはローカルの判断根拠であり、モデルの独立した一票ではありません。実際のTTS発音と不一致、またはWhisperだけでは確定できない場合は確認待ちにし、期待読みに合わせて実測を修正したり同じ語を自動で重複登録したりしません。新規の未確定語は従来どおり有効な同読み2票以上で仮採用し、失敗・判断不能は棄権します。

Whisper比較には原文・確定した基準・元の文字起こしを渡します。文字起こしは事前置換の対象ではありません。登録計画は採用済みの表記と読みからローカルで構成し、最新辞書の重複競合と読戻しを検証します。

入力契約はlocally-resolved-reading.v3です。旧契約の実行は新規ジョブでやり直します。過去の原文・音声・評価・送受信記録は保持します。送受信記録のprompt_charactersとprompt_utf8_bytesは実プロンプトの文字数とUTF-8バイト数であり、モデルごとのトークン数や料金ではありません。

CLI検証と送信量比較の入口はscripts/Validate-ScopedPrompts.pyです。実LLM試験は--liveで明示します。旧方式の全件プロンプトはサイズ計算のためローカルで生成するだけで、再送しません。
