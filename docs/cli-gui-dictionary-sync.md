# CLI辞書更新後のGUI同期規定

制定日: 2026-11-05。区分: 継続的な開発規定・実装時の必須要件。この文書の追加は機能の実装・配布完了を示しません。

## 利用者の要求

CLIで辞書を更新した場合、その都度ではなくてもよいが、一連の処理終了後には起動中のGUIが最新の辞書を取得して表示へ反映する。GUIが起動していない場合は不要。

## 必須の動作

- CLIの単独登録・一括登録・読み修復など、辞書を更新するすべての経路に適用する。VoiSonaのネイティブ辞書と、HTTP TTS用のJSON辞書を同じ規定で扱う。
- 語を登録するたびの再取得は必須にしない。一括処理ではまとめてよいが、一連の処理が終了し、更新が確定して辞書のロックを解放した後には、起動中のGUIが最新辞書を自動取得して反映する。手動更新・タブの開き直し・アプリ再起動を必要としない。
- 処理終了には正常完了のほか、確認待ちへの移行、中断、エラー終了を含める。途中まで確定した辞書更新がある場合も、その実際の状態を反映する。未確定・ロールバックされた更新を登録済みとして表示しない。
- GUIが使用中のTTSエンジン・プロファイル・実際の辞書保存先と、更新された辞書の対応を照合する。同じ辞書を参照するGUIを更新し、別の辞書を参照するGUIへ混在させない。
- 最新の辞書一覧・件数を反映し、表示中の追加候補の重複・競合判定も最新辞書で再計算する。原文や未確定の入力・採否は保持する。表示への反映はGUIのUIスレッドで行う。
- 対象GUIが起動していない場合は同期を省略する。GUIを新規起動せず、起動待ちや同期専用の常駐処理も不要とする。GUIがないことをCLIの辞書更新失敗として扱わない。
- 再取得の要求・完了・失敗をログから追えるようにする。取得失敗を反映成功として記録せず、理由を残す。通知・監視などの実装方式は、この規定を満たす範囲で選択する。

## 受入条件

1. GUIを開いたまま別のCLIから一括で辞書を更新すると、一括処理終了後に操作なしで辞書一覧・件数が最新になる。
2. 同じ条件で追加候補の重複・競合判定も更新され、原文と未確定の入力・採否は保持される。
3. GUIを起動せずCLIだけで更新すると、GUIを起動しないまま処理が終了する。
4. 一部更新後の確認待ち・中断・エラーでも、確定した分だけが起動中GUIへ反映される。
5. 異なる辞書を参照するGUIには更新内容が混在しない。
6. 再取得に失敗した場合、同期成功とせず、原因をログで確認できる。

実装時は、可能な範囲をCLIで起動・操作する複数プロセス試験で確認し、GUIの実際の再取得結果と一覧の状態を検査する。画面の見た目以外の確認にコンピュータユースを前提としない。
